# Prompt 05: 수업 턴 생성

## 입력

- 유효한 세션 JSON
- 학생의 최신 선택 또는 질문
- 현재 학년 밴드
- 연구 팩과 로컬 교사 오버레이가 있다면 그 유효 규칙

## 학생 출력 경계

- 학생 런타임은 `schemas/student-lesson-turn.schema.json`의 `turn`, `student_view`, `evidence_ids`만 직접 생성한다.
- 학생 경로에서 `teacher_view`, 교사용 평가 메모, `memory_delta`를 생성하거나 직렬화하거나 다음 단계로 전달하지 않는다.
- 학생 출력과 교사용 출력을 담은 결합 객체를 먼저 생성한 뒤 숨기지 않는다. 내부 기억 변경은 학생 응답과 분리된 호스트 상태 처리에만 맡긴다.
- 기존 `schemas/lesson-turn.schema.json`과 예시 `lesson-turn.json`은 개발 회귀검사와 접근이 분리된 교사용 fixture일 뿐 학생 런타임 계약이 아니다.
- 오래된 개발 fixture를 공개 가능한 예시로 바꿀 때만 `scripts/project-student-lesson-turn.mjs --from-developer-fixture`를 사용한다. 새 학생 턴은 투영 우회가 아니라 처음부터 학생 schema로 만든다.

## 내부 처리

1. P0 안전·과학 무결성 게이트를 먼저 적용한다. 위해 또는 즉각 위험 신호가 있으면 장면 생성과 선택지를 중단한다.
2. 세션 버전과 `gate.state == RUN_LESSON`을 확인한다.
   `RUN_LESSON` 전이는 조사·다섯 카드 제시·후속 선택·선택 확인·직전 시작 요청이 끝난 뒤, 학생의 다음 메시지 전체 의미가 시작 동의로 명백하고 그 요청이 아직 소비되지 않았을 때만 가능하다. 정확 문자열 일치나 닫힌 단어 목록을 요구하지 않는다. 명시적 부정·취소, 인용·메타 질문, 조건부 표현, 혼합 지시, 선행 동의, 재사용 동의는 전이 근거가 아니다.
3. 학생 입력을 선택, 질문, 교정, 중단 요청 중 하나로 분류한다.
4. 이전 턴 이후 실제로 바뀐 항목만 계산한다.
5. 새 주장마다 근거 상태, 합의 상태, 교과별 근거 유형을 지정한다.
6. 로컬 교사 오버레이가 기본 안전·근거 규칙과 충돌하지 않는지 확인한다.
7. 학생 런타임은 기억 델타를 만들지 않는다. 승인된 호스트가 상태 변경을 별도로 처리하며 그 데이터는 학생 응답으로 전달하지 않는다.
8. `references/lesson-quality-balance.md`의 P0, 근거, 추론, 상태, Canon, 학년, 창의성 감사를 통과한다.

내부 추론 전체를 출력하지 않는다. 학생이 검토할 수 있는 근거와 짧은 이유만 보여준다.

## 학생 화면 형식

```text
### 현재 장면
구체적 장소·시간 또는 상황, 학생 역할, 당장 해결할 문제, 사실을 바꾸지 않는 인물·환경 반응

### 관찰 단서
- [확인됨] ...
- [추론] ...
- [설정] ...
- [아직 모름] ...

### 지금 할 일
학생이 장면 안에서 다음 행동을 고르게 하는 짧은 상황 문장

### 행동 선택
1. 구체적 행동 ...
2. 다른 단서나 장소를 여는 행동 ...
3. 다른 인물·자료와 상호작용하는 행동 ...
- 직접 입력: 다른 행동이나 질문
```

첫 수업 턴은 즉시 장면으로 시작한다. 소리·빛·온도·배치·표시·움직임처럼 학생이 바로 감지할 수 있는 단서를 하나 이상 포함한다. 선택지는 정답 후보, 개념 이름, 검사 항목이 아니라 학생이 실제로 취할 서로 다른 행동 2~4개여야 하며 각 행동은 서로 다른 다음 단서·장면을 열어야 한다.

## 결과 제약

- 학생이 알 수 없는 정보를 역할 지식으로 제공하지 않는다.
- 선택 하나로 전체 결말을 확정하지 않는다.
- 시뮬레이션·설정 결과를 `VERIFIED`로 승격하지 않는다.
- 과학 관찰 전 결과, 수학 증명 전 결론, 문학 해석을 미리 정답으로 고정하지 않는다.
- 이전에 발생하지 않았다고 기록한 사건을 되살리지 않는다.
- 교정된 오류를 다시 사용하지 않는다.
- 근거만 나열해 학생의 선택을 없애거나, 몰입을 위해 미확인 인과를 창작하지 않는다.
- 창의적 디테일은 확인된 사실을 바꾸지 않는 T3/T4 장면 요소와 명시적인 수업 가정에 한정한다.
- `설명해 봐`, `옳은 것을 골라`, `문제를 풀어`를 중심 과제로 삼지 않는다. 교과서식 해설을 먼저 길게 쓰지 않고 학생의 행동 뒤에 필요한 개념을 결과와 단서에 짧게 연결한다.
- 학생에게 전송하기 직전에 학생 전용 schema 또는 동등한 엄격 검증을 적용한다. 검증을 실행하지 못했으면 실행했다고 주장하지 않는다.
