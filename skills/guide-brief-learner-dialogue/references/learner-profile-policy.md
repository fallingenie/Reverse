# 학습자 프로파일 정책

## 목적

프로파일은 학생을 분류하는 문서가 아니라 다음 수업의 지원 방식을 조정하기 위한 최소 기록이다. 학생에게 불리한 추정, 심리 진단, 고정된 학습 유형을 만들지 않는다.

## 기록 층위

1. `ACTIVITY_LOGGED`: 학생 화면에서 실제로 일어난 발화·선택·행동
2. `UNVERIFIED_CLIENT_STATE`: 브라우저가 보낸 구조화 상태이며 서버 사건 원장으로 확인하지 못함
3. `TENTATIVE_PATTERN`: 여러 독립 과제의 학생 기여에서 반복된 잠정 패턴
4. `ASSESSED`: 명시된 평가 과제와 기준으로 교사가 확인한 수행
5. `NOT_ASSESSED`: 현재 기록으로 판단하지 않은 능력

`ACTIVITY_LOGGED`를 곧바로 강점, 숙달 또는 `ASSESSED`로 승격하지 않는다.

## 기여 출처

- `STUDENT_STATED`: 학생이 직접 말함
- `STUDENT_INITIATED`: 선택지 없이 학생이 행동·전략을 먼저 제안함
- `STUDENT_SELECTED`: 중립적인 대안 중 학생이 선택함
- `DEFAULT_ACTION_ACCEPTED`: Agent가 제안한 기본 행동에 동의함
- `AGENT_DEMONSTRATED`: Agent가 안내형 예시를 수행함
- `TEACHER_OBSERVED`: 인증된 교사가 직접 관찰하고 기록함
- `NEEDS_CONFIRMATION`: 출처나 의미를 확인하지 못함

`DEFAULT_ACTION_ACCEPTED`와 `AGENT_DEMONSTRATED`는 강점, 숙달, 오개념 또는 선호의 증거로 사용하지 않는다.

## 필수 필드

공개 베타에서 프로파일은 다음 구조화된 세션 사실만 가진다.

- 가명 학생 ID
- 학교급·학년·과목과 단원 입력 여부
- 선택한 시나리오 ID
- 선택한 행동 ID

학생 자유입력 원문, 교사 자유 메모, 실제 단원 문자열은 프로파일과
Markdown 내보내기에 넣지 않는다. 구조화된 값도 서버가 검증한 사건 원장이
아니므로 `NEEDS_CONFIRMATION`·`UNVERIFIED_CLIENT_STATE`로 두며 관심·선호·능력·오개념으로
해석하지 않는다. 향후 평가 원장이 도입될 때의 각 판단은 다음을 가져야 한다.

- 판단 상태
- 학생 기여 출처
- 검증된 세션 사건 ID
- 적용한 과제와 조건
- 판단이 답하지 못하는 범위
- 교사 확인 여부와 시각

근거 ID가 없거나 Agent와 학생의 기여를 구분할 수 없으면 `NEEDS_CONFIRMATION` 또는 `NOT_ASSESSED`로 둔다. 현재 공개 베타에서는 자유 발화의 개인정보·민감정보를 정규식으로 추측해 선별하지 않고, 자유 발화 전체를 저장·내보내기 경계에서 제외한다.

## 금지 추론

- 행동 횟수만으로 `직접 조작 활동에 강점`이라고 단정
- 제시된 선택지를 끝까지 누른 사실만으로 독립 문제 해결 능력을 확정
- 가상 과학 장면을 실제 실험 수행으로 기록
- 한 수업에서 나타난 행동을 성격·지능·장애·건강·가정환경으로 일반화
- 선택하지 않은 활동을 약점으로 기록

## 향후 평가 원장의 안전한 교정 예시

다음은 활동 로그다.

> 수학 장면에서 제시된 조작 행동 네 번을 선택했다. 각 선택의 세션 사건 ID는 M1~M4다.

다음은 잠정 패턴이다.

> 두 과제에서 학생이 시각 자료를 직접 선택한 기록이 있다. 다만 모든 선택지가 Agent가 제시한 것이므로 독립적인 지원 선호는 확인되지 않았다.

다음은 미평가다.

> 선택지 없이 식을 만들고 설명하는 능력과 응결을 자기 말로 설명하는 능력은 이번 기록으로 평가하지 않았다.

## 내보내기 경계

프로파일은 학생 대화와 분리해 인증된 교사용 서버 경로에서만 저장·내보낸다. 가명 ID를 사용하고 포함 여부를 미리보기에서 명시적으로 선택한다. 학생 역할·평문 키·교사 자기 주장은 인증이 아니다. GitHub Pages 같은 정적 배포에서는 이 기능을 닫는다. Vercel 경로도 환경변수·서버 세션·같은 출처 검증이 없으면 실패 상태로 닫으며, 파일 생성과 다운로드가 실제 성공하기 전에는 완료했다고 말하지 않는다.
